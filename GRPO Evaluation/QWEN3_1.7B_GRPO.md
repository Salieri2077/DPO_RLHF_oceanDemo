# Qwen3-1.7B Ocean GRPO（2026-10-08 ~ 10-09，200 步 + 续训到 400 步）

起点是 [Qwen3-1.7B Ocean SFT](../SFT%20Evaluation/QWEN3_1.7B_SFT.md)。开训前做了 best-of-8 检查：采样均分 1.67，best-of-8 为 2.43，greedy 为 2.28，组内有明显好坏差异，可以开 GRPO。预期是采样回答变好、编造变少，greedy 提升有限。

## 设置

| 项 | 取值 |
|---|---|
| 策略 / 参考 | SFT LoRA 合并进 Base（`scripts/merge_qwen_lora.py`），再加新的 LoRA r32 / α64 训练；参考模型为同一合并模型关闭 LoRA |
| 训练题 | `ocean_sft_val` 中 SFT 未训练过的题（去掉前 512 条和 GRPO 验证集 200 条，去重），约 4.4K 题 |
| 采样 | 每题 8 个，T=0.8，最长 1024 新 token（不截断），每步 4 卡 × 1 题 |
| 奖励 | Qwen2.5-72B-Instruct 对 8 个候选一次打分，顺序随机打乱；组内标准差 < 0.25 的组不更新；不加长度、重复奖励 |
| 目标 | on-policy GRPO（一次 rollout 一次更新），组内标准化优势，KL(k3) β=0.04，按 token 归一 |
| 超参 | 200 步，LR 1e-5，10 步 warmup，余弦到 10%，梯度裁剪 1.0 |
| 代码 | `trainer/train_grpo_hf.py`，评估 `GRPO Evaluation/evaluate_qwen_grpo.py`，串联 `scripts/run_qwen_grpo_chain.sh` |
| SwanLab | OceanHeart-GRPO / `qwen3-1.7b-ocean-grpo-q72b-20261008-2318` |

中断与续训：第 19～30 步 SiliconFlow 对 72B 返回 429 限流（约 7 RPM、2.5 万 TPM），累计 13 组失败后程序保存状态退出。之后给 429 加了 10～60 s 抖动退避（最多 8 次），从第 30 步续训到同一 SwanLab run。续训后又被限流 192 次，全部通过等待恢复，只多失败 2 组。失败组只跳过，不使用伪奖励。

## 训练曲线

| 步数 | 训练奖励（每步新题） | KL | 有效组比例 | 回答 token | 每步秒数 |
|---|---:|---:|---:|---:|---:|
| 1–25 | 1.61 | 5e-5 | 65% | 360 | 35 |
| 26–50 | 1.71 | 2.5e-4 | 67% | 380 | 39 |
| 51–100 | 1.93 | 1.2e-3 | 66% | 381 | 48 |
| 101–150 | 1.92 | 2.7e-3 | 64% | 377 | 47 |
| 151–200 | 1.98 | 4.0e-3 | 65% | 382 | 49 |

验证集（16 题 × 4 采样，训练裁判 Qwen2.5-72B）：第 0 步 1.81 → 第 25 步 1.73 → 第 50 步 1.85 → 第 75 步 1.73 → 第 100 步 2.09 → 第 125 步 2.08 → 第 150 步 2.05 → 第 175 步 2.21 → 第 200 步 **2.33**。

- KL 在第 100 步后进入 1e-3～1e-2 的目标区间，没有失控。
- 回答长度稳定在 360～380 token，没有出现靠变长讨好裁判的现象。正常结束率仍接近 100%。
- 到第 200 步验证奖励仍在上升，尚未收敛。

## 独立裁判配对评估

SFT 测试集前 100 题。SFT 与 GRPO 各生成 1 个 greedy 和 2 个 T=0.8 采样，6 个候选同一请求，由 DeepSeek-V3（与训练裁判不同）正反序各打一次取平均。

| 指标 | SFT | GRPO | GRPO − SFT（95% bootstrap） | 胜 / 负 / 平 |
|---|---:|---:|---|---|
| 采样回答均分 | 1.15 | **1.32** | **+0.17 [+0.02, +0.33]** | 49 / 31 / 20 |
| 每题最差采样 | 0.59 | **0.80** | **+0.21 [+0.01, +0.42]** | 41 / 28 / 31 |
| greedy | 1.52 | 1.64 | +0.12 [−0.11, +0.35]（不显著） | 31 / 16 / 53 |
| ≤ −1 分的回答占比 | 17% | 14% | | |
| 正常结束率 | 100% | 99.3% | | |
| 平均 token | 341 | 348 | | |

分语言：英文 51 题采样 1.20 → 1.45，greedy 1.63 → 1.77；中文 49 题采样 1.10 → 1.18，greedy 1.41 → 1.50。

行为变化，按 300 个回答统计：
- 每千字的数字个数 5.60 → 4.89（−13%），具体数值更少，与"编造变少"一致。
- 每千字的不确定表述（可能、通常、may、likely 等）1.43 → 1.68（+17%）。
- 长度只增加 4%。

裁判噪声：600 个候选中 64 个正反序相差 > 1 分（10.7%）。同一 SFT 模型在本次评估中 greedy 得 1.52，在 SFT 三模型评估中得 1.61。裁判分随同组候选而变，只能在同一评估内比较。

## 结论

1. **结果与开训前的预期一致。** 独立裁判下，GRPO 显著提高了采样回答均分（+0.17）和每题最差回答（+0.21），低分回答减少。greedy 方向为正但不显著，与 best-of-8 检查显示的 greedy 余量小相符。
2. **没有发现明显的奖励投机。** 长度没有膨胀，独立裁判也确认了提升。不过训练裁判看到的提升（+0.52）大于独立裁判（+0.17）：一部分可能是 16 题验证集的噪声，一部分可能是对训练裁判偏好的拟合。
3. **机制解释。** 模型少写具体数字、多用限定语，减少了自信编造，这正是 SFT 阶段发现的主要问题。英文提升大于中文。
4. **尚未收敛。** 验证奖励和 KL 仍在上升，可以继续训练或适当提高学习率。

## 续训到 400 步（2026-10-09）

第 200 步时验证奖励和 KL 仍在上升，因此从第 200 步续训 200 步，记录在同一个 SwanLab run。第一段的余弦计划已把 LR 降到 1e-6，续训改用 WSD：10 步从 1e-6 重新 warmup 到 1e-5，保持到第 350 步，最后 50 步余弦降到 1e-6（`scripts/run_qwen_grpo_continue.sh`）。其余设置不变。第 200 步的 adapter、状态和评估结果都已备份为 `*_step200`。

| 步数 | 训练奖励 | KL | 有效组比例 | 回答 token | LR |
|---|---:|---:|---:|---:|---:|
| 151–200 | 1.98 | 4.0e-3 | 65% | 382 | 1.4e-6 |
| 201–250 | 2.05 | 5.7e-3 | 62% | 385 | 9.1e-6 |
| 251–300 | 2.08 | 9.8e-3 | 54% | 407 | 1e-5 |
| 301–350 | 1.98 | 1.12e-2 | 62% | 405 | 1e-5 |
| 351–400 | 2.08 | 1.10e-2 | 58% | 405 | 5.4e-6 |

验证奖励（第 225～400 步）：2.03、1.98、2.02、2.13、2.19、2.14、2.20、2.06。第 200 步的 2.33 是一个偏高的噪声点，**验证奖励在 2.0～2.2 走平**。KL 在第 300 步后停在约 1.1e-2，即目标区间上沿。有效组比例从约 65% 降到约 58%，说明组内多样性略有下降。

### 三方评估（SFT / 第 200 步 / 第 400 步同组打分）

100 道测试题，每个模型 1 个 greedy 和 2 个采样，9 个候选同一请求，由 DeepSeek-V3 正反序各打一次取平均。

| 指标 | SFT | GRPO@200 | GRPO@400 |
|---|---:|---:|---:|
| 采样均分 | 1.28 | 1.48 | **1.57** |
| 每题最差采样 | 0.80 | 1.05 | **1.10** |
| greedy | **1.64** | **1.65** | 1.59 |
| ≤ −1 分占比 | 16.3% | 13.3% | 13.7% |
| 平均 token | 341 | 348 | 367 |
| 每千字数字个数 | 5.60 | 4.89 | 4.28 |
| 每千字限定语个数 | 1.43 | 1.68 | 1.84 |

| 比较 | 采样均分 | 最差采样 | greedy |
|---|---|---|---|
| @200 − SFT | **+0.20 [+0.06, +0.34]** | **+0.25 [+0.06, +0.43]** | +0.01 [−0.21, +0.19] |
| @400 − SFT | **+0.29 [+0.14, +0.45]** | **+0.30 [+0.08, +0.53]** | −0.06 [−0.26, +0.14] |
| @400 − @200 | +0.09 [−0.05, +0.23] | +0.06 [−0.14, +0.26] | −0.06 [−0.25, +0.13] |

括号为 95% 配对 bootstrap 区间。900 个候选中 81 个正反序相差 > 1 分。

### 解读

1. **采样回答的提升稳定可复现。** 两次独立评估中 @200 相对 SFT 都显著提升（+0.17、+0.20），@400 再提升到 +0.29。
2. **后 200 步收益递减。** @400 相对 @200 只多 +0.09，且不显著；训练裁判的验证奖励也已走平。
3. **greedy 没有提升。** 第一次评估中 @200 的 greedy +0.12，这次是 +0.01，说明那次的 +0.12 主要是裁判噪声。GRPO 的作用是收窄采样分布、去掉坏的尾部：采样均分 1.57 已接近 greedy 1.59～1.65，而 greedy 本身受模型知识限制。这与 best-of-8 检查的预测一致。
4. **需要留意的趋势。** 第 200～400 步里，数字继续减少，限定语继续增加，回答变长 5%。这种变化到目前对独立裁判是净收益，但继续推下去可能变成"含糊、啰嗦"的另一种讨好裁判的方式。再加上 KL 已到 1.1e-2、组内多样性下降，**不建议在当前设置下继续训练**。
5. 后续使用建议：采样场景用 @400，greedy 场景三者相当。@200 的 KL 只有 @400 的约 40%，与 SFT 更接近，是更保守的选择。

## 自动决定训练长度：WSD + 平台检测（2026-10-09）

续训那次是人工判断"走平、该停"。现在 `train_grpo_hf.py` 可以自己做这个判断，规则在 `trainer/rl_schedule.py`。

- **学习率**：`--schedule wsd`，先 warmup，然后保持峰值，直到触发衰减；衰减 `--decay_steps` 步后自动停止。`--max_steps` 只作为预算上限。
- **每次验证的判断**（每 `--eval_interval` 步一次）：
  - 验证奖励：取最近 `--plateau_window` 次的平均。16 题的单次验证噪声约 ±0.1～0.15，所以要先平滑。
  - 训练奖励：取上次验证以来各步的平均。每步都是新题，相当于一个更大的保留集。
  - 两者都没有比各自历史最好值高出 `--plateau_min_delta`，记为一次"未提升"。连续 `--plateau_patience` 次未提升，就判定走平，开始衰减。第 `--plateau_min_steps` 步之前不做判断。
  - KL 不作为收敛信号：只要 LR 不为 0，KL 就会继续增长。它只作为安全上限，窗口平均 KL 超过 `--kl_ceiling` 时也立即开始衰减。
- **默认值用本次 400 步的真实曲线回放标定**（单元测试 `tests/test_grpo.py` 用的也是这组数据）：

| 规则 | 回放结果 |
|---|---|
| 默认：window 3，min_delta 0.05，patience 3，min_steps 100，KL 上限 2e-2 | 第 350 步开始衰减，第 400 步停止，与人工决定一致 |
| patience 2 | 第 250 步就触发，属于被验证噪声误判 |
| KL 上限改为 1e-2 | 第 300 步因 KL 触发 |

- 判断状态（历史、最好值、计数、窗口）保存在 `state.pt` 中，`--resume` 后继续生效。烟测已确认：停在第 3 步后续训，仍在第 4 步按原计数触发。
- 日志：SwanLab 中 `plateau/val_smoothed`、`plateau/train_window`、`plateau/kl_window`、`plateau/stale_evals`、`plateau/decaying` 五条曲线；`completion.json` 记录 `stop_reason` 和 `decay_start`。

```bash
torchrun --standalone --nproc_per_node=4 train_grpo_hf.py --save_adapter <name> --run_name <tag> \
  --schedule wsd --warmup_steps 10 --decay_steps 50 --plateau_patience 3 --max_steps 600 ...
```

局限：判断依据仍是训练裁判（Qwen2.5-72B）的分数。"走平"只说明这个裁判下学不动了，不代表真实质量的上限。停止后仍需用独立裁判评估（`evaluate_qwen_grpo.py`）。
