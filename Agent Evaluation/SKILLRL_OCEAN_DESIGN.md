# 设计：真实海洋观测分析 Agent 与 SkillRL 迁移复现（2026-10-10，M0 审查后）

## 1. 目标与研究问题

**选定一个主数据集：Hugging Face 的 [ESA-philab/OceanDepths](https://huggingface.co/datasets/ESA-philab/OceanDepths)。主任务改为“真实温盐剖面诊断与观测—再分析一致性核验”。**

面向海洋研究人员的实际需求：把一个区域、时期和分析目标转成可复核的分析报告，正确选择变量、筛选有效资料、调用科学计算方法，并解释数据是否足以支持结论。首轮完成混合层诊断与产品偏差核验两个任务族，不再以增加单位换算次数作为主要难度。

研究问题是：**从真实分析经验中提炼和使用技能，能否提高未见区域、时期和请求组合上的科学分析成功率，同时减少完成任务的成本？**

- 30%～70%是希望观察到的**共同工具适配后 ReAct 基线范围**，用于判断是否有研究空间，不是数据集验收条件，也不是必须压低到的分数。
- 不按当前模型的错误挑选最终测试题，不隐去正常产品说明，不故意破坏数据或压缩预算制造失败。
- 若适配后任务已饱和，报告饱和，暂停整组 RL；若几乎全失败，先检查工具适配、任务定义和参考计算。只有真实需求与可学习的错误同时存在，才进入 SkillRL 实验。

现有 v3/v3.1 工具任务已接近满分，但主要是有限单位计算和本地短资料摘录。此前的 1.7B Agent 经过问答 SFT/GRPO 与工具 SFT，不能把这些成绩解释为复杂科学分析已经通过 Agent RL 达到 99%。本任务的 Agent 起点改为官方 Qwen3-1.7B Instruct（见 7.1）。项目和数据调研见 [REAL_WORLD_TASK_RESEARCH.md](</home/anhuang/OceanHeart/Agent Evaluation/REAL_WORLD_TASK_RESEARCH.md>)。

## 2. 数据来源与使用契约

OceanDepths 包含 EN4 派生观测剖面及配对的 GLORYS、OSTIA 等产品；覆盖 2000—2024 年，约949万条剖面记录，标准深度轴为50层。配对变量及有效覆盖并不完整。它提供科学资料，**不提供现成的 Agent 问题、训练轨迹或答案**；这些需要我们构建并核验。[数据论文](https://arxiv.org/html/2608.16373v1)

| 用途 | 采用的资料 | 约束 |
|---|---|---|
| 查询与筛选 | `indices/profiles.parquet`、`indices/variables.parquet` | 保留来源文件、剖面标识、时空坐标和覆盖信息 |
| 科学数值分析 | `data/argo_glors_ostia_ssh.zarr` full enriched 剖面资料 | 读取物理值及元数据，先核验单位、缺测值、QC 编码和配准状态 |
| 势温比较 | EN4 `argo_potm_on_glorys_depth` 与 GLORYS `thetao` 对应字段 | 不把原位温度 `argo_temp_on_glorys_depth` 与势温直接混用 |
| 首轮排除 | uint8 GeoTIFF 和 compact 网格资料作为精密计算输入 | 量化/归一化表示不能冒充原始精度；完整与 compact store 不可互换 |

上述路径以固定版本的本地元数据为准，公开说明见[作者数据卡](https://huggingface.co/datasets/ESA-philab/OceanDepths)。M0 确认 full Zarr 的势温与 GLORYS 温度均以摄氏度表达，不能套用栅格的 Kelvin 转换；层级 QC 保留原层代码或插值两端的较差代码。有效掩膜只表示存在数值，不表示质量合格；实际编码为 int8，读取时检查0/1或使用 `mask == 1`，避免把缺失值转成 True。

当前 revision 为 `d8c813ebd6126066ebe8a13b4c6bae769c8e0a07`；必要剖面资料已下载到 `/data/anhuang/oceandepths`，59,191个文件、约7.73GB，来源与逐文件哈希在 `SOURCE_MANIFEST.json`。下载及 M0 结果见 [OCEANDEPTHS_M0.md](</home/anhuang/OceanHeart/Agent Evaluation/OCEANDEPTHS_M0.md>)。Agent SDK 环境承担读取，训练环境保持原配置；工具先直接按需读取，不根据一次小查询的速度承诺所有请求同样快。

首轮质量规则 `qc_policy_v1`：位置 QC=1，所分析变量的剖面级 QC=1，层级 QC=1，且有效掩膜与有限值检查通过。温度和盐度分别建掩膜，不因盐度剖面被拒绝而丢掉合格温度。位置/变量剖面被拒绝时，即使部分层有值也不得用于正式分析，依据 [EN4.2.2 官方 QC 说明](https://www.metoffice.gov.uk/hadobs/en4/en4-2-2-profile-file-format.html)。当前时间与剖面深度 QC 全为-1，表示不可用，不能强制其等于1，也不能冒称已通过检查；仍核验时间/坐标有限性、范围与深度轴单调性，记录缺少这些质量标记的限制。层级深度 QC 若可用且不合格，也排除该层。

科学解释的边界：

本版本 Zarr 的 `glorys_temporal_status` 仅存储一个非零块，其余块缺失且 `fill_value=null`，当前读取栈的切片会返回未初始化字节。状态以 `profiles.parquet` 为读取来源，并核验记录顺序及状态码0/1/2。其他数组读取前检查缺块与填充值，不能从元数据结构完整推定所有切片都正确；不修改或猜补来源数据。

- 资料已经完成部分深度、空间和周尺度配准。Agent 的工作是审查和利用这些匹配，不把作者完成的配准算成 Agent 的能力。
- EN4 包括不同观测来源，不能全部称为原始 Argo 浮标。当前 full Zarr 按最近源时间配准、空间线性插值。GLORYS 有1,283个名义上约7天间隔的源文件，但来源属性写的是 daily mean；采样间隔不能证明7天平均，在取得 time bounds 或处理证据前只称“约每周采样的最近源时刻场”。OSTIA 等在本库来自日文件，不套用栅格版的周平均说明。
- GLORYS 同化了包含 Argo 在内的观测；偏差核验衡量产品一致性，不能证明独立预测能力。[产品构建说明](https://arxiv.org/html/2608.16373v1)
- 发布包标注 CC BY 4.0；上游 EN4 保留其非商业使用与署名条款，不能只据发布包标签推定全部资料可商业再分发。[发布许可](https://huggingface.co/datasets/ESA-philab/OceanDepths#license)、[EN4 使用说明](https://www.metoffice.gov.uk/hadobs/en4/)

## 3. 首轮真实任务：两个任务族

以下是要构建的需求与输出契约，不是已经存在于 HF 中的标注样例。区域、时间窗和数值结论均须通过实际资料确认。

### A. 温度阈值混合层诊断

**请求示例**：“统计指定海域某年冬季和夏季的温度阈值混合层深度，给出各月可估计剖面数、中位数和四分位数，并说明缺测或深度不足会怎样影响结果。”

Agent 需要完成区域/时间筛选、方法与变量核验、逐剖面计算、按请求聚合及可靠性报告。实际价值是把不同研究请求转成正确的剖面分析流程。

首轮固定方法卡 `mld_temperature_v1`：

1. 明确采用温度阈值法；首轮使用势温字段并在报告中注明，不把结果称为密度法混合层深度。
2. 以10m为参考；深度轴无10m层，必须从其两侧的原生9.573…m与11.405…m合格值线性插值，使用完整坐标而非显示后的四舍五入数值。任一侧不合格则 `no_reference`，不以单侧层代替。参考深度与0.2℃阈值有[de Boyer Montégut 等（2004）的方法依据](https://doi.org/10.1029/2004JC002378)。
3. 从10m向下扫描连续合格层，首次 `|θ−θ10| >= 0.2℃` 时求相邻温度线性插值的阈值交点：目标温度为 `θ10 + sign(θ下−θ10) × 0.2`。不得直接插值两端绝对温差，后者在跨过正负号时会算错。每个估计都输出越界区间及区间宽度，不能把它称为统计置信区间。
4. 首轮**不跨任何不合格/缺测的标准层**。内部缺口且更深处仍有合格值记为 `support_interrupted`，只给最后连续支持深度，不确定缺口内是否已经越界；连续支持到可用末端仍未越界记为 `right_censored`，只给该资料与方法下的下界。二者均不返回精确深度，也不计入可估计剖面的中位数。无10m参考为 `no_reference`，剖面/位置拒绝另记 `profile_excluded`。
5. **先逐剖面计算，再聚合**。统计只代表合格且可估计的剖面，分别报告上述状态数量与分母。跨单个缺层可在 M1 做科学敏感性分析，不据模型分数选择；采用时必须另起方法版本，不能悄悄覆盖 v1。

完整 Zarr 中的 `glorys_mlotst` 不默认当作同定义真值。50层计算是该资料分辨率下的估计；参考程序与独立抽查应核验这一估计，不能宣称恢复原始精细混合层结构。

### B. 观测—再分析一致性核验

**请求示例**：“对指定海域和时期，在共同有效的上层深度比较 EN4 势温与 GLORYS 势温，按深度报告 bias、MAE、RMSE 和样本数；再比较两个月份的产品偏差，说明样本覆盖是否支持这种比较。”

Agent 需要判断物理量是否兼容、选择配对记录与有效掩膜、按请求深度和分组计算、说明时空支持及采样限制。盐度请求只使用有共同有效盐度的记录，不能用温度覆盖数代替盐度覆盖数。

固定方法卡 `profile_consistency_v1`：

- 每个分组、每个深度使用观测和再分析**同批共同合格配对**，执行 `qc_policy_v1` 并要求对应 GLORYS 值有限、`glorys_temporal_status == 0`。状态1的2,057条边界外匹配记录从 B 的默认统计中排除并计数；状态2同样不可用于配对。观测独立任务 A 不因 GLORYS 状态而丢掉合格 EN4 剖面。
- 定义差值为“再分析减观测”；bias 为差值均值，MAE 为绝对差均值，RMSE 为平方差均值开方，`n` 为该深度的有效配对数。
- 深度与聚合权重在请求或公开方法卡中指定；不得把层平均、剖面平均和所有配对点平均混为一个指标。
- 不同月份通常不是同一批剖面。输出各组覆盖和样本数；产品偏差变化不能直接归因为真实海洋变化。
- 无有效配对时不给数值；部分深度可算时交付可算部分及其范围，不把整个请求笼统拒绝。
- 默认从原生5.078…m起报告可用深度，逐层给 n；用户明确要求范围时照其范围分析，不补造浅层值、不因样本少自动判为错误。0.49m保留为可查询层但不默认代表普遍表层覆盖。

两个任务族都允许单剖面诊断、区域统计、月份/季节比较，以及把诊断和产品核验放在同一份研究报告中的真实组合。组合须有分析目的，不规定必须调用几次工具。方法说明向所有基线开放，评估执行与适用性判断，不考隐藏公式记忆。

## 4. 最小工具环境与 Harness 改动

沿用现有 SDK 运行时、动作协议与轨迹记录，新增一个科学分析环境及独立评分器。首轮用有类型约束的科学工具，数值计算交给核验过的程序；不要求1.7B模型手算长数组，也不先引入任意代码执行环境。

| 工具能力 | 责任 | 给 Agent 的结果 |
|---|---|---|
| 查询剖面 | 按区域、时期、来源查询索引 | 数据句柄、候选数、覆盖摘要 |
| 检查/读取资料 | 获取变量定义、单位、QC、时间状态和所需剖面 | 数据句柄、关键字段与缺测摘要 |
| 科学计算 | 提供插值、温度阈值诊断、配对误差、分组统计等标准操作 | 结果句柄、数值摘要、有效数量与失败原因 |
| 读取结果 | 查看请求所需结果表与可核验来源 | 有界表格和结果元数据 |

不提供“输入整道题就返回答案”的工具，也不把正常科学函数拆成无意义的小调用。确定性程序承担数据读取、配准复用和数值计算；Agent 承担根据请求选择数据、方法、筛选、聚合与解释。另设固定流程/规则路由基线，检查 Agent 对这些可变请求是否有实际增量价值。

代码改动范围：

- `agent/sdk.py` 当前绑定旧工具与系统提示，需要按环境接入新工具、提示和评分；复用 Runner、FunctionTool 与现有轨迹格式。
- 保留 `<plan>` 加 `<tool_call>` / `<final>` / `<clarify>` 协议。Base 起点需要 `agent_tokenizer()` 改用 eos 结束助手轮、把未训练的工具标签当普通文本；Instruct 起点的这些 token 已训练，不需要。对话模板（MiniMind 代理模板或 Instruct 自带模板）按 M2 零样本 greedy 对比选择。
- 每步提示包含公开规则/方法卡、检索经验、当前请求、必要分析状态、最近 H 步与当前观察。完整轨迹存盘；输入窗口缩短时保留数据/结果句柄、变量定义和已确认的筛选条件。
- MemoryPolicy 仅支持本轮比较所需的 none、raw_traj、skills、reflexion。短期窗口与长期技能分开；不为增加难度先搭模拟用户。
- 逐轮保存实际 `input_ids`、`completion_ids`、`old_logps` 与调用结果；RL 仅训练模型生成 token，工具输出不参与生成损失。
- 旧 v3.1 环境和评分器保留为回归评测；新任务不用旧的“必须匹配标准调用参数/序列”评分规则。

工具返回大数组的句柄和摘要，避免塞满上下文。调用、上下文和整个 episode 的输入/输出预算在开发集测量后统一冻结；须足够完成经验证的正确流程，不沿用旧任务2048上下文或6次调用作为默认科学限制。Reflexion 的全部重试共享同一总预算。

## 5. 任务构建、规模与隔离

先建立40～60条开发请求，覆盖两类分析、多个区域/季节和自然出现的支持不足情况；每条都有独立参考结果和来源。它们用于接口与可行性验证，不能再当最终泛化测试题。

通过可行性检查后，首轮预算暂按约1000条训练请求、200条开发请求、400条测试请求规划。数量是实施目标，不是已经标注的规模；独立资料块和真实请求不足时缩小规模，不靠同题改写虚增样本数。

- **先切资料，再生成请求**：保留2000—2016训练、2017—2019开发、2020—2024测试，两个年界两侧各排除30天作为初始缓冲，并记录被排除数。配对产品来源若跨分区，同步剔除相关记录；30天是隔离设置，不能保证消除长期相关性。
- 本库缺平台/浮标/航次标识；唯一记录键用 `(profile_source_file, profile_idx)`，不能声称已做平台级独立切分。检查重复键与规范化内容的精确重复，整组归属同一区。以10°×10°空间块组织请求，预留连片海域作空间泛化子集，其边界两侧各留1°缓冲；具体海域在生成请求前声明并冻结。邻近重复与平台相关性无法完全排除，作为局限报告。
- 时间泛化和未见海域结果分开报告；查询必须完全落在所属资料分区，不能用同一个季度/区域查询跨越资料边界。2024仅到7月，不当作完整年份或完整夏季；缺月份的请求交付部分范围并标注支持不足。年际数量和盐度覆盖差异需按年份/季节/变量分层报告。
- 按预定区域、季节、变量和任务族采样，记录真实覆盖分布。不能根据模型失败筛最终测试题；措辞族隔离只能辅助资料隔离。
- 初始技能与教师示范来自训练区。开发集可调方法实现、预算和 checkpoint，并支持技能进化，因此属于适应数据，不作为独立泛化结果。
- 测试前冻结模型、工具、任务清单、方法卡、评分器、SkillBank 和检索规则。测试记录与反馈不进入教师、记忆库或下一轮技能演化。
- 初始规模下先估计区间宽度；统计按原始资料组/时空块进行，不能把共享剖面的多道题当独立样本。

训练轨迹由固定流程或教师产生，并通过独立参考计算接受/拒绝。教师可使用公开工具与方法卡；正确性由验证确认。教师示范和评分器不能共享一套未经独立检查的错误计算。

## 6. 成功定义、奖励与评测

主成功率采用二值规则评分：**完成请求要求的科学结果，且变量、单位、筛选、样本数和来源证据正确**。允许不同正确工具路径，不要求逐字解释或唯一调用序列。

| 项目 | 核验方式 |
|---|---|
| 结果数值 | 独立参考计算；容差由精度、插值及聚合方法确定并冻结 |
| 数据与方法 | 核对 revision、记录/结果句柄、时空选择、变量定义、方法版本和有效掩膜 |
| 统计支持 | 核对各深度/分组有效数、不可估计与截尾数、部分可计算范围 |
| 结论边界 | 主评分只检查预定义的结构化适用性/支持状态；自由说明用于人工抽查 |
| 无法计算 | 参考程序确认资料确实不足，且原因与证据一致才算成功 |
| 失败 | 漏查已有资料、无依据拒答、工具崩溃、虚构数值/来源或未完成请求 |

`<final>` 内交付结构化结果，至少含 `status`、来源/版本、时空范围、变量与单位、方法、结果表句柄、有效数与排除/截尾原因。数值结果可以通过可验证的结果句柄交付，无须模型复写长表。主奖励不依赖 LLM 裁判；图表和文字质量不在首轮主奖励中。

同时报告：

- 总成功率、**可计算任务成功率**、不可计算判断正确率、对可计算任务的错误拒答率，以及各任务族/变量/区域/时期成绩；保留真实可计算比例。
- 数值/方法/覆盖错误、协议错误与预算耗尽分别统计；不能用正确格式掩盖科学失败。
- greedy 与固定采样设置下的成绩；按相同资料组进行配对 bootstrap，报告95%区间。主要 RL 对比至少记录多个随机种子；仅单种子的试运行不作为稳定结论。
- 完整 episode 的累计输入/输出 token、记忆与反思开销、调用数、耗时；教师、训练和进化成本另列。平均单步提示长度不能替代总成本。
- 固定流程/规则路由基线能处理的请求范围及成绩，区分科学数值程序的正确性与 Agent 编排的正确性。

科学成功记为 `S∈{0,1}`。初始优化奖励固定为 `r = S - 0.1 × I(出现过非法协议动作)`，每个 episode 的协议罚项最多0.1；非法协议指格式、工具名称或参数 schema 违规，资料不足不是协议违规。可恢复错误不直接让 episode 永久失败。这是缩放后的罚项设置；科学成功率始终按 S 计算，不用 r 代替。修改公式或引入科学分项奖励须另标实验。

## 7. SkillRL 核心与公平对比

这是 [SkillRL](https://arxiv.org/abs/2602.08234)（[作者代码](https://github.com/aiming-lab/SkillRL)）核心机制的海洋观测分析迁移复现。保留成功/失败经验抽象、层级 SkillBank、技能检索、带技能的冷启动 SFT、GRPO 和递归技能进化。环境、模型、教师、协议和规模均有变化，不直接对比 ALFWorld/WebShop 数字，不称论文结果完整复现。

### 7.1 Agent 起点（2026-10-10 决定）

- 面向任务的能力全部放在 Agent 侧：工具、方法卡、结构化交付、技能库，以及 Agent 的冷启动 SFT 与 RL。

### 7.2 Checkpoint 与对比

在选定起点上定义三个可追踪 checkpoint：

- **C0：共同工具适配。** 只用训练区示范学习新工具与结果格式，所有方法共享。保留 Instruct 起点的零适配成绩作诊断，主比较不用“不会新工具”的低分作为基线。
- **C1：技能 SFT。** 在 C0 上使用经过核验、含检索技能的教师/标准流程轨迹做 SFT。
- **C1_plain：额外示范 SFT 控制。** 用同批核验轨迹，移除技能提示，匹配示范与训练量，区分额外科学示范和技能使用的收益。

C1 与 C1_plain 的监督生成 token 数、更新量一致，额外技能输入长度另报。两者都先评估不做 RL 的成绩，再比较 RL；不能把 SkillRL 的额外 SFT 效果全部归给 RL 或记忆。

| 方法 | 起点 / 更新 | 经验使用 |
|---|---|---|
| ReAct | C0，冻结 | 无长期记忆 |
| Reflexion | C0，冻结 | 公开工具反馈与自检后反思，最多2次重试；报告首次与最终成绩 |
| RawMem | C0，冻结 | 检索训练区核验过的原始成功轨迹 |
| Skills（仅提示） | C0，冻结 | 固定初始 SkillBank |
| Skill-SFT（无 RL） | C1，冻结 | 固定初始 SkillBank |
| Plain-SFT（无 RL） | C1_plain，冻结 | 无长期记忆 |
| GRPO | C0 + GRPO | 无长期记忆 |
| RLOO | C0 + RLOO | 无长期记忆；使用留一基线 |
| Plain-SFT + GRPO | C1_plain + GRPO | 控制额外示范训练 |
| **SkillRL** | C1 + GRPO | 层级技能库 + 进化 |

RawMem 是原始轨迹记忆对比，不声称完整复现 ExpeL。Reflexion 在测试时不能读取隐藏成功标签、参考数值或答案；重试只使用所有方法均可获得的公开执行信息或自检。

四个消融：

| 消融 | 改动 | 保持的控制 |
|---|---|---|
| 去层级 | SkillBank 扁平化 | 尽量保留技能内容、检索设置与记忆 token 上限 |
| 去抽象技能，换原始轨迹 | 冷启动 SFT 与推理的技能上下文均替换为 RawMem，冻结原始轨迹库 | 匹配示范训练量、RL预算和经验 token 上限；与“去进化”固定技能版本比较表示差异，不是完全无记忆 |
| 去技能 SFT | 从 C0 直接使用技能并做 GRPO | 保留共同工具适配；其余设置与完整方法一致 |
| 去进化 | 固定初始 SkillBank | 起点、RL、初始技能与评估预算一致 |

所有方法使用同一工具、公开方法卡、任务和评分器；冻结统一 episode 总预算与经验 token 上限，原始轨迹按上限检索可容纳的完整内容。RL 实验公开各自起点与 KL 参考 checkpoint，统一采样 episode 数、更新上限与单 episode 预算，报告提前终止造成的实际训练 token 差异；额外的 token 匹配实验另列。不同参考模型的影响通过 SFT 控制解释。闭源教师不作为同预算本地基线，只报告示范可完成率及成本。

## 8. 技能生成、训练与进化

- SkillBank 使用通用分析技能、任务族技能和常见错误；每条保留 id、适用条件、原则及证据轨迹标识。初始可按任务族检索，必要时再比较 embedding，不先增加新的检索系统。
- 技能内容包括“先确认势温定义”“每层重算共同有效数”“先算逐剖面指标再聚合”“截尾不能当精确值”等可复用规则；不存逐题最终数值、测试记录或答案表。
- 教师使用 SiliconFlow 的 DeepSeek-V3，提炼成功轨迹的策略和失败原因，生成技能使用示范；API 调用、模型版本、接受率与费用实记，不承诺低于某个未测预算。
- GRPO 初始组大小8，以完整 episode 的优化奖励 r 计算优势，按实际生成步骤/token 训练。启动各 RL 方法前，分别检查该 checkpoint/记忆配置下科学成功 S 与含罚项奖励 r 的组内变化；仅协议罚项有变化不算已有科学学习信号。KL 系数0.01作为试运行起点，各方法使用并记录各自起点作为参考；LoRA 学习率从已有经验范围开始，只在开发集调整。
- 在4×2080Ti上沿用可运行的精度与 LoRA 路径，先测完整 rollout 的显存、耗时和有效 token 吞吐，不照搬论文7B/H100规模或按旧单位任务估算时长。
- 初始按每25个更新步检查开发集各任务族；低于0.4且有足够样本的类别可向教师提交失败证据，每次最多新增3条技能。频率与触发条件属于缩放后的实现设置。
- 失败证据保留请求、关键数据/计算结果和错误原因；不能机械截取最后5步而丢掉决定科学适用性的字段。新增技能去重、核验并版本化，开发集费用计入进化成本。
- 同一采样组使用固定 SkillBank 快照；新技能在下一组生效。old_logps 对应采样时的真实提示与模型，更新时不替换组内提示。
- 不先添加任意代码执行、学习型对话摘要、模拟用户或额外外部数据集。SDK 和科研工具先完成这两类需求。

## 9. 实施里程碑与停止条件

| 阶段 | 工作 | 验收与决策 |
|---|---|---|
| M0：资料核查 | 必要资料已下载；已审查元数据、QC、10m支持、读取与抽样脚本 | 首轮7项规则已冻结；历史抽样统计与修正结果分别保存，时间平均语义仍待源文件证据 |
| M1：参考与环境 | 40～60条开发请求、独立参考计算、结构化评分、新工具接入 SDK | 单独实现参考程序；检查阈值正负号、缺口/末端、位置/剖面QC、时间边界和部分时段；旧 v3.1 回归无行为变化 |
| M2：共同适配与基线 | 训练 C0，运行固定流程、ReAct、教师核验；同题采样8条完整轨迹 | 报告真实成功率、全成功/全失败组比例，分别统计 S/r 的奖励非恒定组比例；确认失败属于实际分析问题 |
| M3：提示与 SFT 控制 | 初始技能、RawMem/Skills/Reflexion，训练 C1/C1_plain | 提示比较与额外 SFT 控制完整，记录技能与教师成本 |
| M4：RL 与消融 | GRPO、RLOO、Plain-SFT+GRPO、SkillRL及四个消融，先短运行再正式实验 | 有非退化奖励信号，起点/预算/参考模型可对照，完成适当多种子运行 |
| M5：冻结测试与报告 | 冻结版本后跑保留测试，汇总按资料组的区间、成本与错误 | 结论只限本任务与数据；明确是否有技能、RL或成本收益 |

**M2 的通过条件是需求真实、参考可信、错误可学习，而不是成功率恰好落在30%～70%。** 若共同适配后依旧接近满分，不启动 M4；若8条轨迹几乎总是同一奖励，先查明原因，不把“强化学习没有提升”误当方法失败。任何新增需求都先证明其实际用途，再建立独立参考；不为凑分数改坏原任务。
