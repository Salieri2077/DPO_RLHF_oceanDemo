# OceanHeart ReAct v3：重做工具 SFT 数据

本轮**只改训练数据**。运行协议、两个工具和评分器与 ReAct v2 完全相同，manifest 仍标 `ocean-react-v2`，所以新旧权重可以在**同一套** react-v2 验证/测试集上逐题对比。没有训练、没有调用在线 API。

## 为什么重做

对 v2 最佳 SFT 权重做“同题换说法”的推理检查（只换措辞，数字、编号、资料库、权重都不变）：

| 题目集 | 原说法 | 只把开头换成“任务：” | 改成训练集句式 |
|---|---:|---:|---:|
| 验证集·计算（25） | 0 | 0 | 22 |
| 测试集·计算（50） | 7 | 12 | 45 |
| 测试集·检索后计算（50） | 0 | 0 | 48 |
| 测试集·检索引用（50） | 1 | 35 | 41 |

模型已经会做，但只认训练里的句式；“任务：”前缀被当成了“该干活了”的暗号。v2 训练数据的问题：计算题 4 种句式、错误恢复 1 种；计算器调用 distance 1375 次而 speed/time 各 125 次；换算只练过 kn→km/h、nmi→km；航次卡全部以 kn 记录；train loss 0.006 时验证集计算题始终 0%。

## v3 改了什么

| 方面 | v2 训练集 | v3 训练集 |
|---|---|---|
| 问法 | 每类 1～4 个固定句式，统一“任务：”开头 | 手写措辞库（`scripts/ocean_react_templates.py`）含题干模板 364 条，训练实际用到 286 个题干措辞族；口语、书面、英文、数字顺序变化 |
| 前缀/结尾 | 固定“任务：”“只回答数值和单位。” | 通用前缀 41 种（训练 33 种，验证/测试各留 4 种），30% 无前缀，与任务类型无关；输出要求 19 种（训练 15 种） |
| 运算 | distance 1375 / speed 125 / time 125 | distance 1996 / speed 1865 / time 1866 |
| 单位 | 只用 km/h、km、h、nmi | 6 种单位、中英文写法（节、海里、米每秒……）；12 个换算方向全覆盖；部分题需先换算再计算，或算完再换成海里/节 |
| 航次卡 | 全是 kn，一种格式 | 航速/航程/时长组合，单位随机（有的需换算有的不需要），多种卡片格式 |
| 澄清 | 缺航速、编号写着 missing、“冲突航次卡”名称直接暴露 | 缺航速/时长/航程六种组合；缺失卡与冲突卡使用和正常卡完全相同的编号与问法，必须先查再判断 |
| 错误恢复 | 历史错误只有一种（operation 写错） | 写错运算、缺参数、多参数、用中文单位名、跨量纲换算；临时故障重试 |
| 防遗忘 | 无 | 回放 600 道 v1 训练题（v1 原句式），针对旧任务回归 84%→48% |

规模：训练 12200 题（含 600 道 v1 回放）、验证 300、测试 300，每个集合六类等量。示范长度 p50 958 / 最长 1144 tokens（上限 2048）。

**隔离**：v3 验证/测试使用训练中未出现的措辞族；训练措辞与 react-v2 验证/测试措辞的最大字符 3-gram 相似度 0.185（门槛 0.3），最长公共片段 6 字（门槛 8）。react-v2 和 v1 验证/测试用过的资料来源、计算参数一律不进入 v3。v3 验证/测试与训练同属一个作者的措辞库（最相近的一对相似度 0.5），只用于挑 checkpoint；**正式对比看 react-v2 验证/测试**（另一作者写的措辞）。

措辞库是人工编写，不是 DeepSeek V3 生成：本机未配置 `SILICONFLOW_API_KEY`，且人工措辞便于逐条审阅、完全可复现。以后想扩充，可把新措辞加入同一个库，生成器会自动做相似度检查。

未加入通用对话回放：现有 Agent 评估不衡量通用问答，且直接混入会和“该查资料时要查”的行为冲突；Agent 权重与问答权重分开保存，原问答模型不受影响。

## 两个版本（A/B）

- `data/processed/react-v3`：沿用 v2 的固定行动说明（“按已知数值与单位计算。”）。主版本，只比较数据多样性的效果。
- `data/processed/react-v3-slots`：任务和最终答案完全相同，只把行动说明改成复述正在使用的数值，例如 `<plan>用航速22.224 km/h和时长3.0 h计算航程。</plan>`，用来测试“先把数字摆出来”能否减少参数填错。

## 训练与对比

`scripts/run_ocean_react_v3.py` 依次执行：四卡烟测（2 步，检查梯度与参数同步）→ 正式 SFT（与 `react-v2-20260927-1046` 相同的起点权重 `ocean_agent_dense-agent-20260927-0232-aligned-sft`、学习率 1e-5、3 个 epoch、累积 8、四卡；按本数据的验证集选最佳权重）→ 在旧模型答过的同一批题上评估 → 逐题配对比较（含 bootstrap 区间），写入 `artifacts/agent/<tag>/comparison.json`。

```bash
OMP_NUM_THREADS=2 python scripts/run_ocean_react_v3.py --tag react-v3-YYYYMMDD-HHMM            # fixed 与 slots
OMP_NUM_THREADS=2 python scripts/run_ocean_react_v3.py --tag react-v3.1-YYYYMMDD-HHMM \
  --variants contrast --compare_to react-v3-20261006-1314-fixed                                  # v3.1，对照 v3
```

### v3 结果（`react-v3-20261006-1314`）

选权重只用 v3 验证集，react-v2 验证/测试对新模型是干净的留出集。

| 评估集（题数） | 旧模型（v2 数据） | v3 fixed | v3 slots |
|---|---:|---:|---:|
| react-v2 验证（150） | 48.7% | 80.7% | 58.7% |
| react-v2 测试（300） | 21.3% | 49.3% | 68.0% |
| v1 旧任务回归（50） | 48.0% | 96.0% | 96.0% |
| react-v3 测试（300） | 21.7% | 74.7% | 70.0% |

fixed 相对旧模型逐题配对提升 +32 / +28 / +48 / +53 个百分点，95% 区间均远高于 0。fixed 与 slots 总体持平（800 题中 541 对 550），但单项差异很大：react-v2 每个集合每类只有一种问法，单项分数基本等于“认不认得这一句式”。

仍未解决：澄清约 35%（编号里的数字被当成数值计算；冲突记录说错字段或直接取一条计算；“编号＋缺航速”去检索后答“未找到资料”）；react-v2 测试的照录题 26%（【】包裹格式训练中没有）；fixed 在 react-v2 测试的检索后计算 2%（查到卡片后把卡片原文当答案）。

## v3.1：针对剩余问题的对比样本（`--recipe react-v3.1-contrast`）

在 v3 基础上只新增类别，原有措辞族的集合划分不变；`--recipe react-v3-diverse`（默认）仍逐字节复现 v3 数据。

| 问题 | 新增样本 |
|---|---|
| 编号数字被当成数值 | 15% 的计算/恢复题带记录编号（如 `HY2024-117`、`850beb8741`），工具参数只用带单位的数；航次卡编号改为多种形式（C/K/R/X 开头、纯十六进制、rec/trip/log 开头） |
| 编号＋缺参数却去检索 | 新类型 missing_id：给出记录编号并说明缺哪个量，直接反问，不调用工具（520 题） |
| 冲突时取一条计算或说错字段 | 冲突题先在行动说明里按字段并列两条记录的数值，例如 `<plan>航速：35 km/h，35 km/h；航行时长：17 h，18 h。</plan>`，再指出冲突字段 |
| 查到卡片后照抄原文 | 650 道“填表/登记/台账”式检索后计算题；另有 400 道“原样摘录卡片原文”的对照题（同样的卡片，要求不同） |
| 括号/引号包裹的照录 | 600 道用 【】「」『』《》“”（）[] 包裹、前面带说明文字的照录题 |

规模：训练 14400 题（含 600 道 v1 回放），验证/测试各 300 题（含每种新类型 10～15 题）；训练措辞与 react-v2 验证/测试的最大相似度仍为 0.185。react-v3 的验证/测试也加入留出排除，v3.1 训练不含它们的资料来源和计算参数。

```bash
python scripts/prepare_ocean_react_v3.py --recipe react-v3.1-contrast \
  --previous data/processed/react-v2 data/processed/react-v3 --output data/processed/react-v3.1
```

注意：这些补丁是看了 react-v2 测试集的失败类型后设计的（措辞仍不重合），因此 react-v2 测试上的提升不再是完全“盲测”的泛化估计；更干净的信号是 react-v3 / v3.1 测试集，长期应另备一套新作者编写的测试题。

### v3.1 结果（`react-v3.1-20261006-1539`，对照 v3 fixed）

同样从 `aligned-sft` 起训，3 个 epoch 共 1350 步，按 v3.1 验证集选最佳（第 1100 步，84.7%）。

| 评估集（题数） | 旧模型 | v3 fixed | v3.1 | v3.1 − v3（逐题配对，95% 区间） |
|---|---:|---:|---:|---|
| react-v2 验证（150） | 48.7% | 80.7% | 82.0% | +1.3（−4.0～+6.7） |
| react-v2 测试（300） | 21.3% | 49.3% | 79.3% | +30.0（+24.3～+35.7） |
| v1 旧任务回归（50） | 48.0% | 96.0% | 98.0% | +2.0 |
| react-v3 测试（300） | 21.7% | 74.7% | 75.0% | +0.3（−3.0～+3.7） |
| react-v3.1 测试（300） | 20.0% | 63.7% | 77.3% | +13.7（+9.0～+18.3） |

- 已解决：react-v2 测试的检索后计算 2%→100%，【】包裹照录 26%→98%；编号含数字不再被当成数值（react-v2 验证的查无资料 4/8→8/8）。
- 部分解决：编号＋缺参数在本库措辞上 0/10→6/10，但 react-v2 的问法（“请为编号…补填航程。日志只提供航行时长，尚无船速数据。”）仍是 1/17：模型先检索编号再答“未找到资料”。
- 未解决：冲突。行动说明能正确并列两条记录的数值，但指出哪个字段不同接近随机（react-v2 测试 0/16，v3.1 测试 5/10），即模型没有学会比较两个数是否相同。
- 副作用：react-v3 测试的计算题少对 5 道（换算后提前作答、多余澄清、同一数字填两次），整体持平。
