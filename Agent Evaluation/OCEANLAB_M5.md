# M5：冻结测试与报告

对应 [SKILLRL_OCEAN_DESIGN.md](SKILLRL_OCEAN_DESIGN.md) 的 M5（2026-10-14 与用户确认：先完成 M4 的开发集正式评估，然后直接进入 M5）。

## 测试请求集

- **生成方式**：与请求集 v2 相同。教师按用户身份和风格写出请求，再由独立抽取核对与请求规格完全一致，然后计算参考答案，并用 SDK 跑一遍标准流程验证能拿满分。脚本为 `scripts/oceanlab_make_requests_v2.py --split test [--scope test-spatial]`。
- **两个测试集**：
  - **test**：200 条。资料为 2020—2024 年测试分区，年界前后各留 30 天缓冲，区域不碰南大西洋预留海域。
  - **test-spatial**：100 条。资料为 2020—2024 年，区域在南大西洋预留海域内部（40～20°S、40°W～0，去掉 1° 缓冲带）。候选为 8 个 10°×10° 方框：纬度起点 −39 和 −31，经度起点 −39、−29、−19、−11。这片海域的资料从未用于训练、开发或技能演化。
- **未见过的提问风格**：每个测试集一半请求（`style_split = unseen`）用训练集和开发集都没用过的写法：
  - 新的用户身份，例如航线规划人员、保险风险分析师、环保志愿者；
  - 新的语气，例如搜索关键词式、语音转写式、先抱怨再提需求、问题清单；
  - 新的坐标写法：中文数字，例如 “南纬二十九度到三十九度”。

  另一半沿用已有风格，因此可以按 `style_split` 拆开，比较风格变化的影响。
- **题型比例**：与开发集相同，换说法 50%、需多想一步 25%、多轮 25%。

## 评估协议

- **脚本**：`scripts/run_oceanlab_eval.py`，与 M2～M4 相同。
  - 预算冻结：12 轮、10 次调用、12,288 上下文、每轮 512 新 token。
  - 本地模型每条请求 1 次 greedy 加 8 次温度为 1 的采样，用批量生成（`--batch 8`），4 卡分片。
  - 教师只跑 greedy，走 API。
- **批量生成核对**：在开发集前 16 条请求上，批量 greedy 与 M3 逐条运行的结果有 15 条逐 token 相同。另 1 条只在最终回答的备注文字里有一个 fp16 近似平局的 token 不同，评分相同。M4 训练中的验证在整个开发集上也与逐条运行完全一致。
- **比较**：`scripts/oceanlab_compare.py`，每个测试集单独比较。
  - 各方法给出带 95% bootstrap 区间的成绩，按题型、支持状态、风格（seen / unseen）、任务族拆开。
  - 两两配对比较：greedy 用 McNemar，采样平均差用配对 bootstrap 的 95% 区间。
- **只跑一次**：测试集结果不用于任何调参、挑选模型或技能演化。

最终测试集：test 200 条（完成 106 / 部分 44 / 支持不足 50，已有风格 103 / 新风格 97），test-spatial 100 条（72 / 17 / 11，51 / 49）。test 中支持不足的比例（25%）高于开发集（16.5%），主要因为 2021 年资料偏少。生成费用 2.32 元，所有请求都通过了参考答案核验和标准流程核验，没有被拒的。

## 结论

1. **RL 有效，并且能推广到新的时期和新的海域**。三个 C1 系 RL 模型相对各自起点，采样平均在 test 上提升 17～20 个百分点，在 test-spatial 上提升 6～11 个百分点，pass@8 达到 87%～91%。
2. **影响最大的是经过核验的教师示范（冷启动 SFT）**：没有 RL 时提升 33.5 个百分点，RL 之后仍有 26.6 个百分点。从 C0 直接做 RL，在新海域只到 33%。
3. **技能库本身在测试集上没有可测的作用**：无论做不做 RL，采样平均的差别都在 ±0.3 个百分点以内。开发集上 C1 带技能 greedy 多出 7.5 个百分点，测试集合并后只剩 +3.7（27 胜 16 负，p = 0.13）。
4. **技能演化在新数据上略有害**：
   - SkillRL 对去进化、对普通 GRPO，采样平均分别差 −2.8 和 −3.1 个百分点，区间不含 0；greedy 的差别不显著。
   - 开发集上 SkillRL 最好（+0.9 / +2.2），到测试集上它掉得最多（−9～−12）。
   - 解释：演化技能来自开发集的失败案例，例如 “去年同月要分别查询”“深度按用户给的数值”。它们修好了开发集的个别请求，却让模型在别的数据上更死板。新风格请求里 SkillRL 也比其他 RL 模型差：test 采样 60.4% 对 63%～66%。
5. **在本任务和本规模上，SkillRL 没有复现论文中的优势**。它的提升来自教师示范加 RL，而不是层级技能或技能演化。
   - 带技能的提示每个 episode 多约 2,000 个输入 token（+16%），没有换来成绩。
   - 本结论限于 1.7B 模型、DeepSeek-V3 教师（论文用 o3）、100 步 RL、单种子，不能推广为对 SkillRL 方法本身的否定。
6. **1.7B 的 RL Agent 在测试集上超过了教师 DeepSeek-V3**（test greedy 70.5%～73% 对 52.5%），差距几乎全在 “按规则交付” 上：
   - 支持不足时正确拒答：78%～86% 对 12%；部分可算：45%～64% 对 18%。
   - 在完成型任务上，教师仍然更强：85.8% 对 74%～76%。
   - 注意教师是零样本，只看了系统提示，没有经过示范或 RL。
7. **其他观察**：
   - 新的提问风格（新身份、语气、中文数字坐标）对 GRPO-C1_plain 和去进化几乎没有影响（greedy 相差在 ±5 个百分点以内）。
   - test-spatial 的 “需多想一步” 题所有本地模型都不超过 33%，教师为 50%。可能是因为这片海域全在南半球，季节要按南半球换算，这类题更难。
   - C0 在 test-spatial 只有 6%。这片海域全在南纬西经，主要原因可能是 C0 常写错正负号。

## 局限

- 每种方法只训练了一个种子。方法之间 2～3 个百分点的差别，需要多种子确认。
- RL 只有 100 步，每步 32 个 episode，相当于 3,200 个训练 episode，远小于论文规模。
- 开发集同时用于训练中的监控和 SkillRL 的演化证据，所以演化的作用只能看测试集。
- 演化加入了我们新增的实测核验（原文没有）。没有核验时会混入明显错误的技能，见 M4 文档。
- 教师只评了 greedy，且没有带技能或示范。
