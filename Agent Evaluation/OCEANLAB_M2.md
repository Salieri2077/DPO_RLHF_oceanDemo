# M2：零样本评估与 C0 示范数据（进行中）

对应 [SKILLRL_OCEAN_DESIGN.md](SKILLRL_OCEAN_DESIGN.md) 的 M2。Agent 起点为官方 Qwen3-1.7B Instruct（设计 7.1），这里记录它在新任务上未经任何适配的成绩、错误类型和实际预算用量，作为 C0 共同适配的诊断依据，不作为主比较基线。

## 设置

- 模型：`/data/anhuang/oceanheart_models/qwen3-1.7b`，无 adapter，非思考模式。
- 环境与评分：M1b 的 `OceanLabHarness` 与评分器；请求为 `oceanlab_dev_v1` 的 48 条。
- 采样：每条请求 1 条 greedy、8 条采样（T=1，与 RL 采样设置相同，种子按请求和样本固定）。
- 预算故意放宽，用于测量：单轮最多 1,024 新 token，上下文 16,384，最多 20 次调用、24 轮。
- 脚本：`scripts/run_oceanlab_eval.py`；结果：`artifacts/oceanlab/m2/zeroshot-instruct-20261010-1650-*`。
- 显存：Qwen3 的分组 KV 在 2080 Ti 上会让 SDPA 退回朴素算法，8K 提示即显存不足。评估脚本先展开 KV 头，16K 提示峰值为 5.8 GiB。

### 模板选择（greedy，规则事先固定）

| 模板 | 成功 | 以合规 `<final>` 结束 | 工具调用无错误 |
|---|---:|---:|---:|
| MiniMind 代理模板 | 0/48 | 12.5% | 21.3% |
| **Instruct 自带模板** | 0/48 | **35.4%** | **30.8%** |

两者首轮提示完全相同，差别只在历史轮次：MiniMind 模板在之前的助手轮里保留空的 `<think></think>`，自带模板会去掉，后者是模型训练时见过的格式。按规则选择自带模板，后续都用它。

## 结果

| | greedy | 采样（8×48） |
|---|---:|---:|
| 科学成功 S | 0/48 | 0/384 |
| 平均奖励 r | −0.054 | −0.047 |
| 出现协议违规的 episode | 54% | 47% |
| 可算任务答成“支持不足” | 7.3% | 15.5% |

- pass@8 = 0：48 条请求的 8 条采样全部失败。
- 43 组的 r 有变化，但都只来自协议罚项。按设计，这不算科学学习信号，所以零样本起点不能直接做 RL。
- 4 个任务族的成功率都是 0。

### 失败在哪一步（432 条轨迹）

| 阶段 | 轨迹数 |
|---|---:|
| 至少有一项要求的分析从未算出 | 203（47%） |
| 都算了，但参数不对 | 186（43%） |
| 所有分析都算出了参数正确的句柄，交付失败 | 43（10%） |

最后一类的交付失败原因：
- 30 条在算出正确句柄后继续读结果、重复调用，直到预算耗尽；
- 11 条在 `<final>` 里抄写数值而不是句柄；
- 1 条状态判断错误；
- 1 条句柄写错。

### 参数错误类型（各 episode 中最接近正确的句柄）

| 参数 | 次数（最接近的句柄） | 主要形式（按全部句柄计） |
|---|---:|---:|
| 分组 | 190 | 季段应合为一组却拆开或数目不对（143），单月或季段的日期边界不对（99），多个月份数目不对 |
| 区域 | 153 | 南纬、西经的正负号或上下限顺序错（108 个句柄），其他框选错误（139 个句柄） |
| 深度层 | 51 | “上层 X 米”误从 0.494 m 起，或把 X 当作起点 |
| 变量 | 7 | 用盐度代替势温等 |

区域错误示例：请求“西经180°—西经170°”，模型调用 `lon_min=-170, lon_max=-170`，工具报错后一再重试仍然错。

### 协议违规与一个环境缺陷

无法解析的动作共 1,561 轮：
- **884 轮是因为 `<plan>` 里出现了 `<`。** 模型把工具报错文字里的“-180 ≤ lon_min < lon_max ≤ 180”抄进了 plan，而协议规定 plan 里不能有尖括号。这类情况集中在 76 条 episode，这些 episode 随后反复重试同一个被拒的动作。**这是环境缺陷**：环境自己的报错文字诱发了协议违规，而且解析错误的提示没有说明 plan 里禁止尖括号。
- 451 轮是标签不完整，例如 `<final>{…}></final>` 多了一个 `>`。
- 其余是 JSON 不完整和未知工具。

其他工具错误：
- 632 次重复失败调用、376 次重复成功调用：模型反复做同一件事。
- 335 次经纬度范围不合法、95 次越过分区、45 次深度范围内没有标准层。

## C0 SFT 学习曲线（`c0-sft-20261010-2037`，已完成）

训练脚本 `trainer/train_oceanlab_sft.py`：
- **样本**：每个助手轮是一个训练样本，输入为该轮推理时的完整提示，只对助手文本和结束 token 计算损失，logits 只在这些位置计算。
- **超参**：LoRA r16/α32，学习率 2e-4，3 个 epoch，有效 batch 16。
- **验证**：留出的 50 条示范算验证损失。

- 每条 episode 2～3 次调用，累计输入约 8.7K token，约 18 秒；协议违规不到 0.6%。
- n500 与 n950 是不同的 adapter，但 432 条轨迹中有 431 条逐 token 相同。两个模型都把示范背到验证损失约 0，输出分布极其尖锐，T=1 采样用相同种子时与 greedy 无异。所以在这批请求上采样几乎没有多样性，RL 没有可学的信号。

## 请求集 v2：真实措辞与新的请求组合

目的：检验 Agent 在没见过的问法和请求组合上能否正确工作，这正是设计第 1 节研究问题中的“请求组合”。C0 仍只用 v1 模板的示范训练。v2 的训练部分留给技能提炼和 RL，开发部分用来调参和评估。

**题型**在评估任何模型之前就已固定（`agent/oceanlab/requests_v2.py`），各占：

| 类型 | 占比 | 内容 |
|---|---:|---|
| 换说法 | 50% | v1 的四种时段形式（单月、季段、季段内逐月、两个月份对比），文字完全换成真人写法 |
| 需多想一步 | 25% | 当地季节（按区域所在半球的气象季节换算月份；跨年季节写作“2017/18年冬季”）、季节内逐月、与前一年同月对比 |
| 多轮对话 | 25% | 第一轮是一个 v1 形式的请求，由 oracle 完成并交付；用户追问一次，改动为以下之一：换变量、只看某个月、拆成逐月、改深度、加上混合层、区域平移 10° |

任务族比例与 v1 相同：混合层 37.5%、势温一致性 21%、盐度一致性 16.5%、综合报告 25%。

**文字生成与核对**（教师模型为硅基流动上的 DeepSeek-V3，`agent/oceanlab/teacher.py`，调用结果全部缓存）：
- **写作**：程序随机抽取用户身份（12 种，如预报员、渔业技术员、本科生）和风格（8 种，如口语、正式邮件、分条列点、中英混杂），把要包含的内容告诉写作模型，并禁止照搬 v1 模板的句式。
  - 坐标由程序换算成 6 种真实写法之一（度数加字母、口语、带正负号、中心点加范围、简写、英文），写作模型必须原样使用其中的数字和方位字。试点发现，让模型自己换算时它常照抄示例里的半球。
  - 年份必须明确写出，不能用“去年”这类没有基准的说法；如果提到海域名称，必须确实位于该坐标范围内。
- **核对**：另起一个提示，只给请求文字和公开约定，独立提取出区域、分组、分析、变量、深度、差值方向和额外要求，必须与规格完全一致。
  - 不一致就换一个身份重写，最多 4 次。
  - 差值方向写成“观测减再分析”的直接驳回。试点中出现过一次，写作提示也已要求按方法卡写“再分析减观测”或不提方向。
- **配额**：每个“类型×任务族”组按 110% 抽样，按抽样顺序取前若干条通过核对的，补足计划数量。取舍只看文字是否忠实，不看任何 Agent 的表现。
- **核验**：每条最终请求都要算参考结果，工具侧与参考侧一致才保留；还要用 oracle 经 SDK 走一遍（多轮任务先重放第一轮的调用），评分 S=1 才保留。

**环境改动**：新增 v2 系统提示（`OceanLabHarness(prompt="v2")`）。它把 v1 的分组句改为按语义分组，并补充季节约定和多轮规则（按最新要求交付，符合要求的旧句柄可以复用）。v1 提示不变。多轮任务开始时先重放上一轮的工具调用，让旧句柄在新一轮里有效。

**试点**（12 条，三类都有）：
- 首次试点 0/12 通过。原因一：核对把方法卡规定的标准统计量当成了“额外要求”。原因二：写作模型照抄坐标示例里的半球。
- 改为程序换算坐标、明确标准输出不算额外要求后，12/12 通过（9 条一次通过），参考结果与 oracle 检查都通过，费用 0.06 元。

## C0 在开发集 v2 上（greedy，诊断）

`c0-n950-devv2-greedy-20261011-0127` 的设置：C0（n950，用 v1 提示训练）、v2 提示、200 条请求、只跑 greedy。

| | 开发集 v1 | **开发集 v2** |
|---|---:|---:|
| 科学成功 | 100% | **29.5%** |
| 换说法 / 需多想一步 / 多轮 | — | 33% / 6% / 45% |
| 可算任务成功 | 100% | 26% |
| 支持不足时正确拒答 | 100% | 46% |
| 可算任务答成“支持不足” | 0 | 18% |
| 平均调用 / 累计输入 token | 2.2 / 8.7K | 4.9 / 22K |

- **失败分布**：参数错 71，其中区域 57、分组 29、深度层 5、变量 4；预算耗尽 32，都是同一个调用反复重试直到调用上限；句柄写错 26；漏交分析 6；用错工具 4；状态判断错 2。
- **区域错误**：主要是半球符号丢失。例如“170°W–180°W”填成 170～180，“40-50S”填成 40～50。按坐标写法统计的错误率：
  - 英文简写 15/34、度数加字母 10/37、中心点加范围 10/26 最高；
  - 口语写法 3/28 最低，它与 v1 的“北纬…西经…”最接近。
- **需多想一步的请求几乎全错**：当地季节 13%，与前一年同月对比 0%，季节内逐月 0%。
- **多轮任务中，追问不需要重新推断的改动反而容易**：只看某月 82%、换变量 64%；加上混合层 0%。

**解读**：C0 在 v1 上的满分，靠的是熟悉模板的写法，而不是理解请求。换成真实措辞和新组合后掉到约 30%，错误集中在“文字→参数”的理解，以及出错后反复重试。这类错误可以通过经验（技能）和 RL 学习，也落在设计期望的 30%～70% 区间的下沿。注意 C0 用 v1 提示训练、用 v2 提示评估，提示有差异；正式基线需要在 v2 提示下重新训练 C0（下一步）。

## C0（v2 提示，共同起点）：`c0p2-sft-20261011-1804`

C0 就是“共同工具适配”的冷启动 SFT，训练内容只有工具用法和交付格式。
- **示范**：与 v1 C0 相同的 500 条旧模板示范，按 v2 提示重新渲染，除系统提示外逐条一致。
- **训练**：42 分钟、303 次更新，验证损失 1.35 → 0.0001。
- **评估预算**：按 M2 实测冻结为单轮 512 新 token、上下文 12,288、10 次调用、12 轮。正确流程最多 4 次调用。

**RL 信号**（每条请求 8 条采样）：
- pass@8 为 36%，高于 greedy 的 22.5%。
- 46/200 条请求（23%）的 8 条采样有成有败，这些请求的科学成功 S 有组内变化。
- 128 条全部失败、26 条全部成功。
- r 有变化的组共 88 个，其中 42 个只是协议罚项不同。

按设计第 8 节的启动条件，科学成功 S 已经有非退化的组内变化，可以开展 RL。但信号集中在换说法和多轮的部分题型。需多想一步的题 pass 率很低（与前一年同月 0.6%、当地季节 7%），只靠 RL 采样很难碰到正确解。这正是技能（例如“S/W 为负数”“南半球冬季为 6～8 月”）可能起作用的地方。

## 结论

1. 零样本 Instruct 会用这些工具，也大致理解流程：查询 → 计算 → 读结果 → 交付。但 S 为 0，pass@8 也为 0，而且没有科学奖励信号。因此 C0 冷启动 SFT 是必要的，这与设计一致。
2. 需要通过 C0 示范学会的内容按影响排序：
   - 把请求文字转成参数：分组、经纬度符号、深度起点；
   - 交付格式：句柄而不是数值，算完就交付；
   - 遵守协议，并能根据报错修正而不是重复。
3. 修改环境：报错文字不用尖括号，解析错误要说明 plan 的限制。改完后用 greedy 复测零样本，作为最终环境下的记录。
