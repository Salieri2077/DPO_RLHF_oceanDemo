## 开发请求 `oceanlab_dev_v1`（48 条）

预声明抽样（种子 0），不使用任何模型结果：

- 候选块：完全落在开发分区、不触及预留海域及其缓冲区的 10° 块，按开发期剖面数分成三档。候选月份：2017-02～2019-11（扣除年界缓冲）。
- 配额：混合层 18 条，势温一致性 10 条，盐度一致性 8 条，综合报告（混合层 + 势温一致性）12 条。每类在三档密度间轮流抽块。
- 时段形式按任务族随机：单月、三个月季段、两个月对比、季段内逐月。
- 一致性请求的深度：上层 50/100/200/500 m，默认从 5.078 m 起；25% 的请求明确要求包括 0.49 m。
- 请求文本写明区域、时段、变量、深度范围与要求的统计量；措辞只在形式上变化。

| | 完整 | 部分可算 | 支持不足 |
|---|---:|---:|---:|
| 混合层 | 15 | 2 | 1 |
| 势温一致性 | 6 | 2 | 2 |
| 盐度一致性 | 5 | 0 | 3 |
| 综合报告 | 8 | 3 | 1 |
| 合计 | 34 | 7 | 7 |

- 支持不足来自抽样自然产生的稀疏块和月份（7 条请求在所选时段内没有剖面）。部分可算主要来自明确要求的 0.49 m 层、两个时段中一个为空、或部分深度没有配对。
- 南北半球 26 / 22 条；每条请求涉及 0～4,141 条剖面。
- 状态定义：混合层以各组可估计数 > 0 为有支持；一致性以每个"组 × 深度"单元 n > 0 为有支持。全部有支持为 complete，全部没有为 insufficient，其余为 partial。

每条请求都保存：结构化规格（区域、组与月份、分析、方法卡、QC 版本、数据 revision）、参考结果（各组状态计数、可估计深度与越界区间宽度的四分位；逐层 n/bias/MAE/RMSE；时间状态排除数）、所用剖面集合的 sha256，以及请求级状态。

## 校验

- **两套实现一致**：48 条请求逐组、逐层比较状态计数、四分位、n、bias、MAE、RMSE，误差 < 1e-9，没有不一致而被剔除的请求。
- **人工构造用例**：两套实现都通过阈值正负号翻转（正确 27.5 m，旧算法给 25 m）、第一层即越界、10 m 任一侧缺失、内部缺口、覆盖末端未越界（含中途无更深合格值）、剖面被拒绝、type-7 分位数、QC 规则、时间状态排除、分区缓冲等用例。
- **人工抽查表**：每种状态各取一条真实剖面，列出原始 θ、掩膜、层 QC、深度 QC、合格判定，以及 θ10 插值和交点的逐步计算，可手算核对。其中包括一条"上一层在 θ10 下方、越界层在上方"的真实逆温剖面（白令海 4 月），说明阈值正负号规则在真实数据中确实会遇到。

### 工具

| 工具 | Agent 决定的参数 | 返回 |
|---|---|---|
| `query_profiles` | 区域 `[lat_min,lat_max)×[lon_min,lon_max)`、起止日期（含首尾） | 资料句柄 `ds_*`、所在分区、剖面数、逐月剖面数（含零月份）、GLORYS 时间配准状态计数 |
| `inspect_dataset` | 资料句柄、变量（势温 / 原位温度 / 盐度） | 来源变量与单位、对应 GLORYS 量、有值剖面和层数、有值层的层级 QC 码计数、剖面级与位置 QC 码计数、深度轴，以及“掩膜只表示有值”的说明 |
| `compute_mld` | 资料句柄、变量、`qc_policy`（`qc_policy_v1` / `finite_only`）、分组 | 结果句柄 `res_*`、方法卡或诊断标记，各组剖面数、五类状态计数（零也列出）、可估计深度与越界区间宽度的四分位数（无可估计时为 null） |
| `compute_consistency` | 资料句柄、变量、`qc_policy`、`temporal_filter`（`nearest_or_exact` / `any`）、`depth_min`、`depth_max`、分组 | 结果句柄、方法卡或诊断标记，各组剖面数、剖面级 QC 拒绝数、时间配准排除数、有配对层数、无配对层列表、n 范围；全部组合计不超过 24 行时附逐层表 |
| `read_result` | 结果句柄、组、`cursor` | 分页的完整表（混合层为逐剖面结果，一致性为逐层统计），`next_cursor`、`done`；首页附来源参数与 revision |

- **分析选项都有实际用途，用途写在提示里**。`finite_only` 用来检查 QC 筛选的影响，`any` 用来做配准敏感性分析。这两种结果都标为“诊断结果，不能作为正式结果交付”。Agent 中途试算、发现问题后改用正式规则，仍算成功；只有把诊断句柄当作正式结果交付才判科学失败。
- **原位温度只能检查，不能计算**：GLORYS `thetao` 是势温，温度阈值方法卡也规定用势温。两种计算工具都会做物理量兼容检查，拒绝原位温度，返回 `incompatible_variable` 错误和原因，不生成句柄。混合层计算同样拒绝盐度。
- **配准选项改名为 `nearest_or_exact`**，与来源属性 `flag_meanings` 一致：状态 0 包含最近时刻配准，不表示观测与再分析时间完全相同。
- **空组和缺失要区分清楚**：工具保留请求的每个组和每个深度层；空组返回零计数，缺失的统计量为 null。`request_status` 遇到没有任何组或深度单元的结果会报错，不再因 `all([])` 为真而返回 complete。
- **分区按查询范围检查**，不看查询碰巧返回了哪些剖面：
  - 训练、开发、时间测试三个环境禁止读取预留海域及其 1° 缓冲带。
  - 空间测试环境 `test-spatial` 只能读测试年份内、整体落在预留海域缓冲带以内的区域，缓冲带仍禁止。
  - 日期以整天计：开发分区可用 2017-01-31～2019-12-01，训练分区截至 2016-12-01，测试分区从 2020-01-31 开始。
  - 每次查询后再逐条核对剖面的 `partition_of` 标签，不一致记为环境错误。
- **单次查询不超过 2 万条剖面**。
- **观察长度上限为 1,200 token**，超长时只截短模型看到的摘要，句柄始终保留。完整结果和来源参数都存在登记表中，随轨迹保存，逐剖面表只保存在内存中供 `read_result` 读取。
- **错误分两类**：参数不符合 schema（缺参数、未知参数、类型或枚举错误、日期格式错误）记为协议违规；越界、句柄不存在、变量不兼容等是普通请求错误；工具内部异常记为环境错误。

### `<final>` 与评分

`<final>{"status":"complete|partial|insufficient","results":{"mld":"res_…","consistency":"res_…"},"notes":"…"}</final>`。结果只能用 `<final>` 标签交付；未加标签的文字视为非法动作，Agent 会收到错误提示并可以重试。

科学成功 S = 1 要同时满足下列条件。评分器还会把各条失败原因分别统计。

1. `<final>` 能解析为合约规定的 JSON 对象，请求涉及的每个分析都给出了句柄。
2. 每个句柄都是本轮由对应工具生成的，而且规范化后的计算语义与请求一致：
   - 区域边界；
   - 各组日期覆盖的集合，组名和顺序不算条件，按完整日历月判断；
   - 变量；
   - QC 规则 `qc_policy_v1`；一致性分析还要求 `nearest_or_exact`；
   - 实际深度层集合。
   各组的记录集合由环境自检核对，见下文。
3. 声明的状态与参考状态一致。支持指“有效支持”：混合层看各组可估计数，一致性看各“组×层”的配对数。
   - 拒答也必须交付显示零支持的正式句柄，所以不查资料直接拒答会失败。
   - 查询错误、越界和预算耗尽产生不了句柄，不能充当证据。
   - 参考状态可算而回答 insufficient，单独记为错误拒答。

`complete` 只表示要求的输出都有数值支持，不代表样本足以支撑强科学结论。

**环境自检与模型成绩分开**：
- 本轮生成的每个结果句柄都按该句柄自己的参数，由独立参考实现重算；比较内容包括剖面数、记录集合 sha256、状态计数、四分位数、逐层 n/bias/MAE/RMSE、时间配准排除数和 QC 拒绝数。
- 只有这里不一致，或工具抛出内部异常，才算环境错误。Agent 选错 QC、变量、配准或分组仍然是模型失败。
- 汇总函数遇到环境错误会直接报错。这类错误要先修复，再重跑受影响的任务，不能剔除后继续比较。
- 评分结果（包括 `metrics`）对 Agent 隐藏，不进入提示、记忆，也不进入测试时的 Reflexion 反馈。

优化奖励 r = S − 0.1 × I(出现协议违规)。协议违规包括：
- 无法解析的动作或未知工具；
- 工具参数违反 schema；
- `<final>` 不符合合约。

越界、资料不足等普通错误不算协议违规。

### 验证

**内存小数据测试**（`tests/test_oceanlab_env.py`）覆盖了开发集里没有的情形：
- 有剖面但零可估计（缺 10 m 参考）。
- 有剖面但零配对（只有边界外配准）。如果交付 `any` 的句柄，会记为 `temporal_filter` 参数错误。
- 两个月份中只有一个能算，应答 partial；空组仍出现在句柄里，计数为零。
- 不查资料就拒答（缺分析句柄）、编造句柄、状态判断错误。
- 组名和顺序不同但日期覆盖相同时判成功；日历覆盖少一天时，即使记录集合相同也判错。
- 中途用 `finite_only` 试算、最后交付正式句柄判成功；交付诊断句柄判失败。
- 原位温度可以检查，但两种计算都拒绝。
- 分区边界：触及缓冲带的空区域、年界缓冲、空间测试只能读预留海域。
- 分页读取。
- 篡改句柄数值后报环境错误，且不影响模型成绩判定。
- 协议违规只扣奖励，不影响 S。
- 模型提示中只出现本环境的系统提示和工具，不出现旧工具。
