# OceanHeart：真实海洋任务与配套数据调研

日期：2026-10-09。本文是任务选择建议，不替换 `SKILLRL_OCEAN_DESIGN.md`，不改变训练代码、数据和权重。

## 结论

建议将下一阶段主任务改为 **真实海洋观测数据分析：温盐剖面诊断与观测—再分析一致性核验**。用真实时空记录、科学方法的适用条件和可复核的数值结果形成难度。海洋极端事件调查作为扩展评测，海洋热浪识别作为第二阶段功能。

Hugging Face 上已有可用的数据来源，但要区别原始科学数据、现成任务定义和完整 Agent 训练集。这里核实了数据卡、文件说明和公开任务样例；没有下载并执行科学数据，也没有测量当前 1.7B Agent 在新任务上的成绩。

## 1. 对项目与现有成绩的认识

- 原始主线：MiniMind Dense 63.9M / MoE，通用预训练、海洋 SFT/LoRA、DPO/GRPO、OPD/MOPD。
- 当前成熟基座主线：Qwen3-1.7B-Base → 海洋问答 SFT → 问答 GRPO 400 步 → v3.1 工具 Agent SFT。问答 GRPO 和多轮工具 Agent RL 是不同实验阶段。
- Agent 环境：`agent/ocean.py` 提供 SQLite 本地检索与有限的距离、速度、时间、单位换算；`agent/react.py` 提供协议与规则评分；`agent/sdk.py` 接入 OpenAI Agents SDK。
- v3/v3.1 已改善措辞多样性、参数抽取、澄清、恢复与照录。训练隔离和轨迹记录可以继续复用。

核对 `artifacts/agent/*-eval-*/result.json` 后，主要测试成绩如下：

| 模型 | react-v2 test（300） | react-v3 test（300） | react-v3.1 test（300） |
|---|---:|---:|---:|
| Qwen 0.5B，工具 SFT | 99.3% | 99.7% | 99.0% |
| Qwen3 1.7B，海洋 SFT+问答 GRPO+工具 SFT | 94.0% | 100% | 99.7% |
| Qwen 3B，工具 SFT | 99.7% | 100% | 100% |

0.5B/3B 达到满分不需要新增 Agent RL。1.7B 的 v2 失败主要集中在一个缺参数措辞族。因此现有结果支持“当前任务已饱和”，尚不能支持“Agent RL 已把复杂海洋问题解决到 99%”。证据与误差说明见 [基座对比](BACKBONE_COMPARISON.md)。

这些单次/贪心评估的高分不等于训练采样组没有奖励差异；组内信号仍须用实际随机 rollout 测量。这不改变应优先选择有实际价值任务的判断。

现有检索任务主要核验从本地短资料中摘录并引用，部分资料来自合成 OceanInstruct，航次卡是模拟记录。它适合工具协议回归，但不能代表开放文献研究或真实海洋业务分析。

## 2. 配套 Hugging Face 数据

| 数据集 | 已核实内容 | 推荐用途 | 仍需补齐 |
|---|---|---|---|
| [ESA-philab/OceanDepths](https://huggingface.co/datasets/ESA-philab/OceanDepths) | EN4 观测剖面与 GLORYS、OSTIA、海面高度、表层盐度配对；约 949 万剖面、50 个标准深度；2000—2024 年，页面约 119 GB | **主要数据源：剖面诊断、多源对齐、产品偏差核验** | 真实需求题、参考计算、输出契约、训练轨迹；不是现成问答集 |
| [osunlp/ScienceAgentBench](https://huggingface.co/datasets/osunlp/ScienceAgentBench) | 102 个跨学科任务；当前应使用 `verified` split；确认有海温 EOF 与南大西洋温盐剖面任务 | 先验证科学分析接口；保留外部任务作评测 | HF 仅提供任务注释；完整数据、参考程序和评分程序从作者链接另取；海洋任务少 |
| [miracle10/EarthVerse](https://huggingface.co/datasets/miracle10/EarthVerse) | 全领域 405 题、199 个事件；HF 包含问题、证据、参考答案和评估代码，约 979 MB | **扩展：海洋热浪、珊瑚白化及沿海事件的多源调查** | 海洋子集数量与逐题适用性要审查；不能将 405 题都算海洋题；官方评分含 LLM judge |
| [PranavKonijeti/viirs-sst-daily-nonNRT](https://huggingface.co/datasets/PranavKonijeti/viirs-sst-daily-nonNRT) | NASA VIIRS 日海表温度科学质量产品的社区镜像；2012—2026 年、约 4 km；有质量字段，约 63.1 GB | 第二阶段的 SST 分析与产品交叉检查 | 存在云覆盖和缺日；常用 30 年热浪基准不能只靠这份数据 |
| [kawihss/ais-inland-vessel-trajectories](https://huggingface.co/datasets/kawihss/ais-inland-vessel-trajectories) | 德国 2025 年三个观测站的真实 AIS 衍生轨迹，约 2.04 GB；船舶级切分；5 分钟历史与5分钟未来窗口 | 备选：航道船舶运动分析、预测产品核验 | 属于内河/港口场景；经过清洗、重采样和归一化，不适合作为原始 AIS 缺测或异常的真值 |

OceanDepths 提供完整剖面 Zarr 和网格化输入两种表示。科学数值核验应优先核查完整剖面的物理量；供图像模型使用的归一化/量化栅格不能直接当原始精密观测。其 EN4 派生记录也不能全部解释为原始 Argo 浮标记录。[数据布局与温度定义](https://huggingface.co/datasets/ESA-philab/OceanDepths)

## 3. 首选问题：温盐剖面诊断与多源一致性核验

### 实际需求

海洋研究人员拿到观测与再分析产品后，需要确认数据能否用于某个分析，选择兼容的记录与物理量，计算剖面或区域指标，并保留来源和处理依据。Agent 的价值在于处理不同研究请求、选择与核验分析流程；固定请求仍应由标准程序直接完成。

下面是建议采纳的功能示例，不是已标注或已运行的基准题：

1. **剖面与混合层诊断**：给定区域和时期，筛选覆盖参考深度的有效温盐剖面，按事先定义并经专家认可的混合层准则计算结果，输出剖面数、深度覆盖、指标与无法计算的原因。
2. **观测—再分析一致性核验**：比较匹配记录的 EN4 势温与 GLORYS `thetao`，按深度报告偏差、误差和有效样本数；先确认物理量、空间支持和时间匹配是否兼容。
3. **表层与次表层对照**：比较同一区域同一时期的表层温度与上层剖面结构，说明数据是否支持“表层变化同时出现在更深层”的判断。若问的是异常，须额外明确历史基准；不能仅用 SST 推断次表层变化。

第一轮先完成前两类，第三类作为扩展。混合层、密度或热含量涉及的温度、盐度、压力约定必须先固定；选择经核验的标准计算方法，而不是让模型背公式。

### 难度从哪里来

难度来自真实数据中的覆盖差异、缺测、深度支持、温度定义以及观测与产品的时空匹配。任务成功需要正确识别数据适用性，完成分析并证明结果；不能只判断工具有没有运行。

这些条件应从数据自然出现，并由任务所需科学标准决定。不得根据 1.7B 的错误反向挑最终测试题，也不需要加入额外换算链、故意坏文件或无关干扰来降低分数。

对原始 Argo 质量控制另有真实需求，但 OceanDepths 是处理后的配对数据。若要评价原始浮标 QC，需另取 GDAC 原始/延迟模式记录及其质量字段。Argo 对混合层深度、热含量等敏感应用有明确的数据选择建议，不能把派生数据的有效值掩膜冒称原始 QC 标记。[Argo 数据使用说明](https://argo.ucsd.edu/data/data-faq/)

### 评分与参考答案

- 保存结构化结果：记录/数据版本、区域、时间窗、变量定义、方法、有效样本数、数值与单位、不能计算的原因。
- 用独立参考计算与人工抽查核验数值，不依赖模型回答措辞；容差由数值方法和数据精度确定。
- 核验来源与筛选条件，但接受不同正确工具路径；旧评分器中“必须与标准调用参数/序列完全一致”的规则不宜原样迁移。
- 原始数据缺失时，奖励科学上有依据的“无法计算”。工具崩溃或没找到明明存在的数据不能获得同等奖励。
- 图表用于交付与检查；主奖励优先来自可核验的科学结果，不来自图表外观。

## 4. 现成科学任务与事件调查的使用边界

### ScienceAgentBench：可立即着手验证的入口

在当前 `verified` 预览中确认：

- 48：冬季太平洋海表温度的主 EOF 空间模态。
- 50：海表温度 EOF 与对应时间序列，包括 ENSO 变化。
- 55：南大西洋温盐剖面分析与绘图。

48/50 很接近，不应视为两个独立任务族。它们是科学接口验证和外部评测的种子，规模不足以单独支撑海洋领域的大量 RL。原任务部分图表评分需 GPT-4o；若改成纯数值核验，要标明是改编任务，而不是原版分数。[verified 任务预览](https://huggingface.co/datasets/osunlp/ScienceAgentBench/viewer/default/verified)

完整基准含参考程序与评估程序，作者要求从配套链接取 `benchmark_verified.zip`，并明确不要在线再分发解压数据。不要把 HF 的几百 KB 注释文件误认为完整科学数据。[作者的访问与评测说明](https://github.com/OSU-NLP-Group/ScienceAgentBench)

### EarthVerse：适合扩展，不能直接等同生产需求

公开任务中确认包含 2013—2016 年东北太平洋 The Blob、2016 年大堡礁热浪/白化、2023 年 Florida Keys 白化，以及 Sandy 沿海洪水案例。它们提供事件级多源证据，适合检验来源选择与分析结论是否相互支持。[海洋任务样例](https://huggingface.co/datasets/miracle10/EarthVerse/viewer/default/tasks?p=3)、[珊瑚白化样例](https://huggingface.co/datasets/miracle10/EarthVerse/viewer/default/tasks?p=4)、[沿海洪水样例](https://huggingface.co/datasets/miracle10/EarthVerse/viewer/default/tasks?p=1)

但部分题使用基准定义的综合分数、门槛或优先级指标。真实事件背景不能自动证明每个派生指标有实际业务价值。采用前逐题核验方法来源，优先选择实际观测、热应激、时间/空间支持与证据充分性问题。其官方评测也包含 LLM 判断，不能直接接入后声称“全规则奖励”。[论文与评测边界](https://arxiv.org/html/2608.23525v1)

它是 2026 年新发布的基准，本文未独立复跑或验证其全部科学结论。原任务材料为 CC BY-NC 4.0，软件部分为 Apache-2.0，第三方证据保留上游条款。[发布许可](https://huggingface.co/datasets/miracle10/EarthVerse/blob/main/LICENSE.md)

## 5. 第二阶段：海洋热浪识别与证据核验

实际需求：研究或生态监测人员需要识别事件起止、持续时间、强度、空间范围和数据可信度，而不仅是问“水温是否很高”。常用 Hobday 定义结合季节性第 90 百分位阈值和至少连续 5 天，并采用长期历史基准。[NOAA 热浪指标说明](https://ecowatch.noaa.gov/thematic/marine-heatwaves)

HF 的 VIIRS 科学质量镜像适合提供高分辨率 SST 与质量字段，但自身时间跨度不足以建立常用 30 年基准，且有云覆盖和缺日。长期基准宜从 [NOAA OISST v2.1](https://www.ncei.noaa.gov/products/optimum-interpolation-sst) 获取。跨产品比较还要明确网格、采样和温度定义，不能直接套用不同产品的分位阈值。

OceanDepths 的主要栅格时间支持为周尺度，因此不能直接替代热浪识别所需的逐日序列。热浪与珊瑚 Degree Heating Weeks 也是不同指标；需要分别采用其原始方法，不把两者混用。

这条需求有实际意义，但从科学数据到 Agent 题目、参考事件标签与轨迹仍需要建设。未核实到“同时包含长期日 SST、真实业务题和全部 Agent 轨迹”的一站式 HF 训练集。

## 6. 对 SkillRL 复现计划的调整建议

SkillRL 关注从成功与失败经验提炼可复用技能、层级检索、技能使用 SFT 与 RL 期间的技能进化。新任务应检验这些机制能否改善数据分析和跨场景迁移。[SkillRL 原论文](https://arxiv.org/html/2602.08234v1)

建议保留现有 harness、SDK、轨迹记录与训练骨架，替换数据环境和评分器。旧 v3.1 保留为回归集。新科学工具应明确输入输出和适用条件，保留有效记录与来源，不把整块海洋数组塞进提示，也不把整个任务封装成一个自动给最终答案的工具。

计划中的成功率 30%—70% 应改为**基线观察项**。若自然任务太容易，报告其饱和；若全失败，先区分接口、示范、领域知识和推理瓶颈。不能为了得到漂亮对比而删掉易题、缩短上下文、限制工具或追加无关步骤。

实验至少补齐以下控制：

1. **共同的新工具适配**：ReAct、GRPO 等须获得可比的新环境说明与工具示范，不能把未经适配的旧 Agent 与经过新任务 SFT 的 SkillRL 比较后归因于技能。
2. **技能 SFT 但无 RL**：除现有 Skills 提示基线，还需独立报告完整冷启动 SFT 后的成绩，分离额外 SFT、技能库与 RL 的收益。
3. **固定程序/规则路由参考**：核验参考分析本身能完成任务，并了解固定流程已能解决多少实际请求。若所有请求只有同一固定流程，Agent 的增量价值也应重新审视。
4. **同等推理和训练资源**：Reflexion 重试计入推理预算；报告首次与总成功率。教师、技能进化和检索的 token/时间开销计入对应方法成本。
5. **隔离到原始数据层**：按事件、时期、区域和原始记录组划分，不能只按问题哈希。一个事件的多道题、同一剖面的改写题不能跨训练/测试；相关题的区间应按事件或原始记录组重采样。
6. **技能进化与测试分开**：用于生成技能的开发集已参与适应，不再作为独立泛化证据；最终测试在权重、技能库和选择规则固定后使用。

海洋环境、模型规模、教师与训练方式均已改变，因此成果应称为“SkillRL 核心机制的海洋领域迁移复现”，不将新基准成绩与论文原始 ALFWorld/WebShop 数字直接比较。

## 7. 最小可行验证

建议在启动整组 RL 前完成：

1. 用 ScienceAgentBench 的海洋任务验证数据读取、分析结果输出与科学工具接口；记录改编内容。
2. 从 OceanDepths 取一个固定版本的小子集，覆盖真实区域与时期，先完成剖面诊断和观测—再分析核验两类需求。
3. 固定科学方法和参考计算，邀请领域人员审查任务是否有实际用途以及证据能否支持答案。
4. 建立几十道开发题，先比较标准程序、适配后的 ReAct、仅技能提示与更强教师。题数只是起步建议，不预设成功率。
5. 确认失败是有科学意义且可学习的，再扩大训练数据并开展 GRPO、RLOO、SkillRL 与消融；独立测试集提前封存。

数据访问失败、领域方法不明确、教师也全失败，都不能靠“加大 RL”解决。若只有某一措辞族失败，则仍是当前基准遇到的问题，不足以证明新需求更复杂。
