## 冷启动结果，不是 GRPO 增益

固定50道验证题，贪心生成：

| 模型／阶段 | 计算 | 检索摘录 | 两工具任务 | 总成功率 |
|---|---:|---:|---:|---:|
| 原始 Dense GRPO | 0/20 | 0/20 | 0/10 | 0% |
| 格式存在错误的初次工具 SFT | 0/20 | 0/20 | 0/10 | 0% |
| 修正格式后的工具 SFT | 20/20 | 16/20 | 7/10 | 86% |
| 正式 Agent GRPO step 0 | 20/20 | 16/20 | 7/10 | 86% |

修正后工具 SFT 训练3 epochs，共189个 optimizer steps，处理6000次样本。其32题×4次随机诊断得到：73/128条轨迹成功（57.03%）、141/153次调用合法（92.16%）、27/32题有组内奖励差异（84.38%），三类任务均有成功样本，因此通过既定门槛。

验证的86%与随机诊断的57.03%不能直接相减：题目和采样方式不同。后续评估 RL 增益应比较相同50题、相同贪心生成设置下的 step 0 与最佳／最终 checkpoint。

## 保留的失败与修复

初次 SFT loss 降到约0.01，但工具输出大量缺少开头 `<tool_call>`。原因是复用的问答 `SFTDataset` 在 deterministic 模式删除空 thinking 前缀，而 Agent rollout 保留该前缀，造成训练／推理格式差异。

修复使用独立 `AgentSFTDataset` 保留模板，不修改原有问答 SFT 默认行为。回归测试逐轮断言训练 token 前缀与 rollout 实际前缀相同，且下一监督 token 正确。随后从原始 Dense GRPO 重新训练，不续接有问题的 SFT 权重。旧试跑保留在 `artifacts/agent/dense-agent-20260927-0232/` 及其阶段目录，原来的SwanLab曲线和权重未删除。

另外，首次辅助 judge 评估对被截断的轨迹传入了空 `final`，不能代表实际生成质量；旧 `judge_baseline.json` 保留但不用于比较。已修复为评分实际最后生成片段，并增加回归测试。有效基线是旧流水线目录的 `judge_baseline_actual.json`：DeepSeek V3 对固定20道资料题评分均值−3，20次成功、无API错误。正式终点评估使用相同修正规则。

SFT的提升不是GRPO的提升；检索摘录成功也不是闭卷海洋知识提升。完整训练是否进一步改善任务成功率，留待训练结束后用固定验证／测试结果判断。
